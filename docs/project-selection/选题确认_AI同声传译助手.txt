选题确认：AI 同声传译助手
版本：v0.1
日期：2026-06-05

一、最终选择
本项目最终选择：
题目二：AI 同声传译助手

二、题目要求摘要
用户经常需要观看英语或其他外语演讲、技术分享、国际会议或网课。项目需要通过 AI 能力，将单向音频流实时、流畅地翻译成中文，并以字幕或语音形式呈现，帮助用户跟上内容节奏。系统还需要具备修正能力，能够自动纠正之前识别或翻译的错误。

三、选择理由
1. 用户价值更直接
同声传译助手解决的是“听不懂外语就无法获取信息”的问题，用户打开即可获得即时帮助，不需要长期训练后才感知价值。

2. 使用场景更广
该产品可用于技术分享、国际会议、网课、直播、企业培训、跨境协作和内容学习，覆盖学习与工作两类高频场景。

3. 演示效果清晰
输入一段外语音频，系统实时输出中文字幕，并在后续上下文明确后修正前文错误，演示路径直观，评委容易理解产品价值。

4. 产品差异明确
基础翻译并不是差异点。核心差异应放在实时字幕体验、上下文翻译、术语一致性、历史字幕修正和双语记录导出。

四、MVP 定位
首版 MVP 聚焦“实时字幕同传”，不把中文语音播报作为首要目标。

MVP 目标能力：
1. 支持英语音频输入。
2. 实时识别源语言文本。
3. 实时翻译为中文字幕。
4. 字幕支持临时状态和最终状态。
5. 支持对最近若干句字幕进行自动修正。
6. 支持会话级双语记录。
7. 支持基础术语表，为技术类内容保持翻译一致性。

五、暂缓能力
以下能力放到 MVP 之后：
1. 中文语音播报。
2. 多语种完整支持。
3. 会议软件插件。
4. 浏览器插件。
5. 高级降噪和说话人分离。
6. 字幕文件多格式导出。

六、建议功能拆分
1. docs: 确认选题与产品范围
明确最终选题、MVP 边界、后续 PR 拆分。

2. feat: 新增音频输入与会话创建
实现用户创建同传会话、选择音频来源和基础状态管理。

3. feat: 新增流式识别结果展示
实现音频到源语言文本的实时展示，先允许 mock 数据，后续接真实 ASR。

4. feat: 新增中文翻译字幕展示
实现源语言文本到中文字幕的流式展示。

5. feat: 新增字幕修正机制
通过 segment_id、version、status 维护临时字幕与最终字幕，并允许系统更新历史字幕。

6. feat: 新增术语表
支持用户配置术语，提升技术内容翻译一致性。

7. docs: 补充 README、依赖说明和演示流程
保证评审能快速理解并复现项目。

七、核心数据对象建议
1. Session
字段包括 session_id、source_language、target_language、status、started_at、ended_at。

2. AudioChunk
字段包括 chunk_id、session_id、start_time、end_time、audio_format、vad_state。

3. TranscriptSegment
字段包括 segment_id、source_text、start_time、end_time、confidence、status、version。

4. TranslationSegment
字段包括 segment_id、target_text、display_text、status、version、revised_from、glossary_hits。

5. RevisionEvent
字段包括 segment_id、old_text、new_text、reason、confidence、created_at。

6. GlossaryItem
字段包括 source_term、target_term、domain、priority、note。

八、评审表达重点
1. 不只是翻译，而是实时理解助手。
2. 不只是输出字幕，而是能基于上下文修正之前的识别或翻译错误。
3. 不只是通用语言转换，而是支持术语表和领域一致性。
4. 不只是一次性 Demo，而是有明确模块拆分、PR 记录和持续迭代过程。

九、当前结论
后续所有开发工作围绕“AI 同声传译助手”展开。三个候选议题的初步方案继续保留在 docs/project-plans 中，作为选题调研与决策依据。
