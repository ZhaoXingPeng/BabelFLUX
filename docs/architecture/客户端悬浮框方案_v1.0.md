# 客户端悬浮框方案 v1.0 — Web 唤醒内置客户端悬浮窗

版本：v1.0
日期：2026-06-06
依赖基线：`docs/architecture/桌面客户端阶段规划_AI同声传译助手.txt`（P0 / 6 模块 / deep link 协议 / 安全原则）

---

## 0. 一句话结论

桌面悬浮框 = **同一个 `FloatingCaption.vue` + 同一套 design tokens，挂载在一个 Tauri 透明置顶窗里**。Web 通过 `lingosync://floating/start` 携带「一次性 handoff token + 会话参数」唤起客户端，客户端用 token 换取 WS 凭据、订阅同一份字幕事件流。**样式天然一致（靠组件复用，不是靠对齐规范），桌面只在「窗口外壳 / 2D 拖拽 / 锁定穿透 / 工具条收纳」四处做必要增强。**

## 1. 背景与现状

### 1.1 目标
回答两个问题并给出可落地的 1.0：
- **方案设计**：Web 端如何唤醒内置客户端悬浮框（启动协议 / 安全 / 降级 / 会话接管）。
- **样式设计**：悬浮框长什么样，是否与 Web 「悬浮字幕」一致，交互如何。

| 位置 | 现状 | 1.0 缺口 |
| --- | --- | --- |

## 2. 核心决策（含「是否与 Web 一致」的回答 + 选型修正）

| # | 决策 | 说明 |
| --- | --- | --- |
| D1 | **悬浮框与 Web 悬浮字幕样式一致 —— 是，且靠组件复用实现** | Tauri overlay 用 Vue 渲染，直接挂载同一个 `FloatingCaption.vue` + 同一套 tokens。一致性是「同源」而非「对齐」，零分叉。 |
| D2 | **维持 Tauri 路线**（规划已定，不变） | 复用 Vue3+TS、Rust 系统能力、体积小；overlay 复用组件是决定性加分项。 |
| D3 | **deep link 仅作启动指令，凭据走一次性 handoff token** | 落实规划「七.7.5 不携带敏感凭据」。token 短时（≤60s）、单次使用。 |
| D4 | **统一圆角 8px / 暗色半透 surface** | 修正：不引入大圆角，与全站 8px 一致。 |
| D5 | **桌面「锁定」= 停拖 + 全窗鼠标穿透**，解锁靠全局热键 | 比 Web 的 `captionPinned`（仅停拖）更强；穿透用 `setIgnoreCursorEvents`。 |

## 3. 方案设计（架构）

### 3.1 模块映射（复用规划中的 6 模块）

| 模块 | 1.0 职责 | 关键 API / 依赖 |
| --- | --- | --- |
| **Shell** | 启动、单实例、协议注册、窗口生命周期 | `tauri-plugin-single-instance` |
| **LauncherBridge** | 解析 deep link，提取参数 + token，路由到 OverlayWindow | `tauri-plugin-deep-link` |
| **OverlayWindow** | 透明置顶窗，挂载复用版 `FloatingCaption`，管理拖拽/锁定/透明度 | `transparent+decorations:false+alwaysOnTop`、`setIgnoreCursorEvents` |
| **SessionBridge** | 用 handoff token 换 WS 凭据、连后端、订阅事件 | WebSocket（复用 Web 客户端逻辑） |
| **LocalSettings** | 持久化窗口位置 / 字号 / 透明度 / displayMode | Tauri Store / 本地文件 |
| **CaptureAdapter** | **1.0 不做**（overlay 仅作展示消费端），P1 接系统音频 | — |

> **1.0 范围澄清**：悬浮框是「字幕展示面」，音频仍由现有 Web/会话管线产生；客户端只消费 WS 事件。系统音频采集是 P1（PR25），不进 1.0。

### 3.2 唤醒时序

```
 Web 工作台                后端                客户端(Tauri)
    │                       │                      │
    │ 1. 用户点「投送到桌面悬浮窗」                  │
    │ 2. POST /sessions/{id}/handoff               │
    │ ───────────────────►  │                      │
    │ 3. 返回 handoffToken(≤60s,单用)              │
    │ ◄───────────────────  │                      │
    │ 4. location = lingosync://floating/start?...&token=h_…
    │ ─────────────────────────────────────────►  │ (协议唤起/单实例聚焦)
    │ 5. 启动超时计时(≈1.5s)                        │ 6. LauncherBridge 解析参数
    │                       │   7. 用 token 兑换 WS 凭据 ◄──┤
    │                       │ ──► 8. 返回 wsToken           │
    │                       │   9. SessionBridge 连 WS + 订阅│
    │                       │ ──► session_started / *_segment / revision_event / source_sync_state
    │ 10a. 收到客户端「已接管」回执 → 标记「已投送」 │ 10. OverlayWindow 渲染字幕
    │ 10b. 超时未唤起 → 弹「下载客户端」轻提示       │
```

### 3.3 deep link 协议 v1.0（在规划基础上做最小增量）

保持规划已定的 `lingosync://floating/start` 与参数，**仅新增 `token`**，并明确语义：

| 参数 | 取值 | 必填 | 说明 |
| --- | --- | --- | --- |
| `sessionId` | string | 否 | 复用 Web 会话；缺省=客户端新建会话 |
| `source` | `system-audio` / `microphone` / `browser-tab` / `screen-window` | 否 | 采集意图；1.0 透传记录，采集在 P1 |
| `sourceLanguage` | `auto` / `en` / `zh` / `ja` … | 否 | |
| `targetLanguage` | `zh` / `en` / `ja` … | 否 | |
| `displayMode` | `floating` / `bilingual` / `translation-only` | 否 | 字幕布局，见 §4.5 |
| `token` | string | **是(有 sessionId 时)** | 一次性 handoff token，≤60s，单次 |

示例：
```
lingosync://floating/start?sessionId=s_8f3a&source=system-audio&sourceLanguage=auto&targetLanguage=zh&displayMode=bilingual&token=h_9Qx2…
```

### 3.4 安全：一次性 handoff token（落实规划「七.5」）

- deep link 是**世界可写**的——任意应用都能调起 `lingosync://`，因此**绝不能在 URL 里放长期凭据**。
- 流程：Web 向后端换一个 `handoffToken`（短时 ≤60s、**单次使用**、与 `sessionId` 绑定）→ 放进 deep link → 客户端 `SessionBridge` 拿 token 向后端兑换真正的 WS 会话凭据。
- token 被旁路截获也只有 ≤60s 单次窗口，且不等于账号凭据。

### 3.5 未安装客户端的降级（乐观唤起 + 超时回退）

Web 无法可靠探测「客户端是否安装」，1.0 采用业界标准：
1. 点击即尝试 `lingosync://…`（乐观唤起）。
2. 起 ≈1.5s 计时 + 监听 `visibilitychange`/`blur`：若期间页面失焦 → 视为唤起成功。
3. 超时仍在前台 → 弹**克制的**「下载桌面客户端」浮层（含下载入口 + 「继续用网页悬浮字幕」），不打断、不啰嗦。
4. 成功唤起后用 `localStorage` 记 `lingosync.clientSeen=1`，下次直接走唤起、不预弹提示。

### 3.6 会话接管与 Web/桌面共存

- 桌面接管后，**Web 默认不强制关闭自己的悬浮字幕**，而是把工作台状态标记为「已投送到桌面」，并提供「隐藏网页字幕」开关——避免「两个都在显示」的尴尬，由用户选。
- 单实例：第二次 `lingosync://` 唤起路由到运行中的实例，**更新现有 overlay 的会话参数**（1.0 只维持一个 overlay 窗）。

### 3.7 Tauri 工程能力清单

**插件**：`deep-link`（协议）、`single-instance`（聚焦已运行实例）、`global-shortcut`（解锁/显隐热键）、`positioner`（边缘吸附，可选）、`autostart`（P2）。

**悬浮窗口配置**：
```jsonc
{
  "transparent": true,        // 窗口透明，圆角/阴影由 CSS 自绘
  "decorations": false,       // 无系统标题栏（整条自定义拖拽）
  "alwaysOnTop": true,
  "shadow": false,            // 关系统阴影，用 CSS box-shadow
  "skipTaskbar": true,        // 可选：不占任务栏
  "resizable": true
}
```

## 4. 样式设计

### 4.1 一致性原则：复用，不是对齐

桌面 overlay 直接 `import` 现有 `FloatingCaption.vue` 与 tokens → 字体、配色、间距、双语/仅译文布局、动效**全部同源**。规范一致性是副产物。

**组件共享机制建议**：
- 目标态：抽 `shared/caption/`（pnpm workspace 包），`frontend` 与 `desktop` 同时依赖。
- 1.0 最简：`desktop` 用路径别名 `import` `frontend/src/components/workbench/FloatingCaption.vue` + `styles`，先接通、后抽包。（**避免 copy 导致分叉**。）

### 4.2 设计语言对齐表（全部引自 `main.css`）

| 维度 | 取值（token / 实测） | 来源 |
| --- | --- | --- |
| 圆角 | `8px`（全站统一） | `border-radius: 8px` |
| 悬浮面板背景 | `rgba(11,12,15,.82)` 暗色半透 | `.floating-caption-panel` |
| 边框 | `1px rgba(255,255,255,.14)` | 同上 |
| 阴影 | `0 18px 46px rgba(0,0,0,.34)` | 同上 |
| 源文 | `--stage-src #c9cdd4`，`0.62em`，弱 | `.floating-source` |
| 译文 | `--stage-dst #ffffff`，大，`font-weight:850` | `.floating-translation` |
| 强调/状态 | 琥珀 `--stage-accent #e0a458`、绿 `--stage-ok #5fb48a`、红 `#e27670` | `.sync-dot.*` |
| 正文字体 | Geist Variable（非 Fraunces；衬线只用于标题） | `:root font-family` |
| 字号档 | 小 16 / 中 clamp(18,2.1vw,28) / 大 clamp(22,3vw,38) | `.size-*` |
| 透明度滑杆 | 55–100 step 5 | `.floating-caption-toolbar input` |

### 4.3 桌面相对 Web 的 5 个必要差异

| # | 差异 | 为什么 |
| --- | --- | --- |
| 1 | **窗口外壳**：原生透明无边框窗（圆角/阴影 CSS 自绘） | 没有浏览器容器 |
| 2 | **2D 自由拖拽**：整条 `data-tauri-drag-region` / `startDragging()` | Web 是页内纵向 transform；桌面要移动 OS 窗口 |
| 3 | **锁定 = 停拖 + 全窗鼠标穿透**（`setIgnoreCursorEvents`） | 盖在视频/会议上时鼠标要能点到下层 |
| 4 | **工具条 idle 自动收纳、hover 显现** | Web 工具条常驻；桌面要「高级且简洁」 |
| 5 | **整窗透明度（40–100）独立于字幕卡背景** | 整窗可调淡以减少遮挡 |

> 唯一**有意视觉增强**：桌面盖在任意应用上方，建议给字幕卡加 `backdrop-blur(10–12px)` 提升可读性（Web 当前无模糊）。已标注，便于评审取舍。

### 4.4 悬浮窗视觉规范 + 布局

**常态（hover 显工具条）：**
```
 ╭─────────────────────────────────────────────────╮  ← 整条可拖拽
 │  ● LIVE        源+译 · 仅译文   A−  A+   ▢   ✕    │  ← 工具条 idle 隐藏 / hover 淡入
 │                                                   │
 │   This is the recognized source sentence.         │  ← 源文 0.62em · --stage-src
 │   这是被识别到的源句对应的中文译文。                │  ← 译文 大 · --stage-dst · weight 850
 ╰─────────────────────────────────────────────────╯
   radius 8 · bg rgba(11,12,15,.82) · shadow 0 18 46/.34
```

**锁定态（鼠标穿透）：**
```
 ╭─────────────────────────────────────────────────╮
 │   这是被识别到的源句对应的中文译文。                │   ← 仅字幕，无工具条，边框淡化
 ╰─────────────────────────────────────────────────╯
   🔒 已锁定 · 鼠标穿透 · 按 Ctrl/⌘+Shift+L 解锁   (toast 3s)
```

工具条按钮沿用现有 ghost 风格：`min-h 28 · radius 6 · bg rgba(255,255,255,.07) · border rgba(255,255,255,.12)`。

### 4.5 三种 displayMode 渲染定义 + 与现有 `form.style` 映射

| `displayMode` | 含义 | 映射现有 `form.style` | 渲染 |
| --- | --- | --- | --- |
| `bilingual` | 双语 | `双语字幕` | 源文(0.62em,弱) + 译文(大,强) |
| `translation-only` | 仅译文 | `仅译文` | 仅译文，字号更大 |
| `floating` | 紧凑单行 | （**1.0 新增 compact**） | 仅最新一句译文，单行省略，最小占位 |

### 4.6 状态与反馈（复用 `.sync-dot` 语义）

| 后端 `source_sync_state` / 连接态 | `.sync-dot` 类 | 颜色 | 文案 |
| --- | --- | --- | --- |
| listening / syncing / recovered | `.listening`/`.syncing`/`.recovered` | 绿 `--stage-ok` | LIVE |
| lagging | `.lagging` | 琥珀 `--stage-accent` | 延迟 |
| missing / error / 断连重连 | `.missing` | 红 `#e27670` | 重连… |

`revision_event` 复用现有 `.revision-float` 琥珀微提示（译文被修订时一闪）。

### 4.7 动效

复用 `FloatingCaption` 已有的 GSAP（Draggable + 进出场），新句 `streamToken` 淡入上移、旧句下沉，全部受 `@media (prefers-reduced-motion)` 收敛——`main.css` 已有该 media query，桌面自动继承。

| 交互 | 行为 |
| --- | --- |
| 开窗 | 默认屏幕底部居中（或 LocalSettings 记忆位置），GSAP scale/opacity 入场 |

## 6. 1.0 范围与验收

**In**：deep link 带参唤起 + handoff token、单实例聚焦、透明置顶可拖拽窗、复用 FloatingCaption 渲染 mock/WS 字幕、锁定+穿透+热键解锁、字号/透明度/模式/位置持久化、未安装降级提示。

4. deep link 不含任何长期凭据；token 单次失效。

## 8. 命名 / 选型修正清单（用户授权「可修正选型」）

1. **圆角**：统一 `8px`，不引入大圆角（对齐全站）。
2. **deep link 安全**：规划「七.5」落地为**一次性 handoff token**，URL 仅 `+token`。
3. **命名收敛**：`ProductMode(quick|floating)`（`types/workflow.ts`）与 deep link `displayMode(floating|bilingual|translation-only)` 存在 "floating" 语义重叠。约定：**ProductMode 决定 Web 产品形态；displayMode 仅表示字幕布局**。建议后续把 `displayMode=floating` 更名 `compact`（1.0 保留别名，不破坏现有协议）。
4. **工具条**：桌面 idle 收纳 / hover 显现（Web 常驻）——有意差异。
5. **透明度语义**：拆「整窗透明度」与「字幕卡背景」两层，默认只暴露整窗滑杆。
6. **backdrop-blur**：桌面新增 10–12px（Web 无），唯一有意视觉增强。
7. **锁定语义**：桌面「锁定」升级为「停拖 + 全窗穿透」（Web `captionPinned` 仅停拖）。
