## 1. 主屏高度 · 右侧不出滚动条（问题 1）

### 根因
- **入口主屏 `HomeView`**：`.home-shell { min-height:100dvh }`（main.css:117）+ `.home-hero { min-height: calc(100dvh - 92px); padding:56px 0 72px }`（:176）。`home-nav`(约 90px) + `home-hero`(min-height 100dvh−92 **再加** 上下 padding 128px) + 大标题 `clamp(48px,9vw,104px)` + 两卡 + footnote，内容很容易超过一屏 → 右侧竖滚动条。
- **工作台 live 屏**：`.workbench-shell.live { overflow:auto }`（:342）+ `.workbench-grid { min-height: calc(100dvh - 69px) }`（:450）。这里的 `69px` 是对顶栏高度的**硬编码估算**（实际 = 14×2 padding + 两行文字 + 1px 边线 ≈ 69，但只要出现 `errorMessage` 那一行、或字体行高有零头，就超过一屏 → 滚动条）。`.subtitle-column { max-height: calc(100dvh - 69px) }`（:873）同样依赖这个魔法数。

### 改法（定高 + 内栏滚动，彻底消除页面级滚动条）
**工作台**：把 shell 改成"满屏定高的纵向网格"，顶栏 `auto`、内容区 `1fr`，页面本身不滚动，只有右侧字幕栏内部滚动。
```css
/* main.css :342 */
.workbench-shell.live {
  display: grid;
  grid-template-rows: auto 1fr;   /* 顶栏 + 内容 */
  height: 100dvh;                 /* 定高，不再 min-height */
  overflow: hidden;               /* 关键：页面级不滚动 */
  background: var(--stage);
  color: var(--stage-dst);
}
/* :450 去掉魔法数，让 grid 吃满 1fr */
.workbench-grid {
  display: grid;
  grid-template-columns: minmax(0, 1.08fr) minmax(360px, 0.92fr);
  gap: 1px;
  min-height: 0;                  /* 删除 calc(100dvh - 69px) */
  height: 100%;
  background: var(--stage-line);
}
/* :869 字幕栏自身滚动，不再依赖魔法数 */
.subtitle-column {
  display: grid;
  grid-template-rows: auto minmax(0, 1fr);
  min-height: 0;
  max-height: 100%;               /* 删除 calc(100dvh - 69px) */
}
```
> `errorMessage` 那一行（WorkbenchView:94）改为**绝对定位浮层 / toast**，不再占文档流高度，避免它一出现就把 grid 顶出滚动条。

**入口主屏 HomeView**：同样定高，hero 用 `1fr` 居中、上下 padding 收一点，标题 clamp 上限略降，保证一屏放下。
```css
/* :117 */
.home-shell {
  display: grid;
  grid-template-rows: auto 1fr;
  height: 100dvh;
  overflow: hidden;
}
/* :176 */
.home-hero {
  min-height: 0;                  /* 删除 calc(100dvh - 92px) */
  padding: clamp(24px, 4vh, 48px) 0;
}
/* :190 标题上限 104 → 88，给两卡留出空间 */
.home-hero h1 { font-size: clamp(44px, 7.5vw, 88px); }
```
> 移动端窄屏若内容确实放不下，仅在 `@media (max-height: 640px)` 下允许 `overflow:auto`，桌面端始终一屏。

### 美学依据
`frontend-design`：克制的满屏构图、"一屏一焦点"；滚动条是视觉噪音，定高网格 + 内栏滚动是编辑式布局的标准做法。

## 2. 设置弹窗：纯净背景 + 正确默认值（问题 2）

### 2.1 弹窗后面的"奇怪的框"
**根因**：setup 态下 `WorkbenchView` **同时**渲染了两层——
- `<SetupBackdrop v-if="!isLive">`（:74），其 `.setup-backdrop::after { inset:12%; border:1px solid rgba(47,93,80,.08); border-radius:8px }`（main.css:366）就是那个**居中描边方框**，外加一个超大半透明标题"BabelFlux / 巴别流 同传"（:386）。
- `<SettingsDialog v-if="shouldShowSettings">`（:160），其遮罩 `.settings-backdrop { background: rgba(20,22,26,.54) }`（:1155）是**半透明**，于是背板的方框 + 鬼影标题透了出来。

**改法**：setup 态下弹窗永远盖在最上层，背板没有单独露出的时机——直接**弹窗开启时不渲染背板**，并把遮罩做成真正的"纯背景"（加深 + 毛玻璃）。
```vue
<!-- WorkbenchView.vue:74 -->
<SetupBackdrop v-if="!isLive && !shouldShowSettings" />
```
```css
/* main.css:1155 —— 纯净深色毛玻璃，背后不再透出任何框 */
.settings-backdrop {
  background: rgba(15, 17, 20, 0.72);
  backdrop-filter: blur(10px) saturate(120%);
}
/* 顺手去掉这个最容易被误读为"框"的装饰描边 */
.setup-backdrop::after { content: none; }
```
> 这样 setup 态背后是纯净的暖白底（shell 非 live 时 `var(--paper)`）+ 毛玻璃，弹窗悬浮其上，干净。

### 2.2 专业领域默认"通用"
**根因**：`stores/session.ts:316` 写死 `domain: "技术"`（而 `domainOptions[0]` 已经是 `"通用"`，:50）。
```ts
// session.ts:316
domain: "通用",   // was "技术"
```

### 2.3 会话名称：去掉"会议"语义，默认用「时间 + 下划线」
**根因**：`session.ts:315` 写死 `name: "国际技术分享同传"`，既假设了"会议"场景又是固定文案。用户确认格式：**`同传_20260606_1530`**。
```ts
// session.ts 顶部新增 helper（应用代码可正常用 new Date()）
function defaultSessionName(): string {
  const d = new Date();
  const p = (n: number) => String(n).padStart(2, "0");
  return `同传_${d.getFullYear()}${p(d.getMonth() + 1)}${p(d.getDate())}_${p(d.getHours())}${p(d.getMinutes())}`;
}
// :315
name: defaultSessionName(),   // was "国际技术分享同传"
```
> 建议在 `startMode("quick")` / `resetMode` 里**重新调用** `defaultSessionName()`，让时间戳反映"真正开始"的时刻，而不是页面加载时刻。

**连带的"会议"措辞**（用户说"不一定是会议"）一并改中性：
- `WorkbenchView.vue:134` `会议报告` → `同传报告`
- `EndSessionDialog.vue:23` `结束会议` → `结束同传`
- 字段 hint「用于会话报告与导出文件命名」已是中性，保留。

### 美学依据
`minimalist-skill`：默认值不替用户预设场景；时间戳命名零歧义、可排序、直接当导出文件名。

## 3. 语言区字号 + 所有下拉框的设计感（问题 3）

### 3.1 「源语言 / 目标语言」字号太小
**根因**：`.language-pair-field label span`（main.css:1286）`font-size:11px` + `text-transform:uppercase` + `letter-spacing:.12em`——这套是给西文小标签用的，套在中文"源语言/目标语言"上既小又别扭。
```css
/* :1286 */
.language-pair-field label span {
  color: var(--ink-soft);
  font-size: 13px;            /* 11 → 13 */
  font-weight: 700;
  letter-spacing: normal;     /* 中文不要字距 */
  text-transform: none;       /* 中文不要全大写 */
}
```
> 选中的语言值本身是 20px（:1295），够大；问题只在 label。

### 3.2 下拉框丑 / "里面字体不对" / 无设计感 —— 换掉原生 `<select>`
**根因**：项目所有下拉都是原生 `<select>`（`.form-control` 领域/模型 main.css:1348；`.language-pair-field select` :1295）。原生 `<select>` 展开后的**选项列表由操作系统渲染**，用的是系统字体、系统配色——这就是"里面字体似乎不对、没有设计感"的根因，且 `<option>` 的样式跨浏览器**几乎无法定制**。

**改法**：新建自研下拉组件 **`SelectField.vue`**（详见 §9），用「触发按钮 + 浮层 listbox」实现，完全用 App 字体与配色、带 Lucide `chevron-down`、展开走 GSAP/CSS 淡入。**替换全部 3 处下拉**：
- `SettingsDialog.vue:61-63` 专业领域
- `SettingsDialog.vue:100-102` 模型选择
- `LanguagePairField.vue:44 / :54` 源/目标语言（保留中间 ⇄ 交换按钮与右下角语言码 strong）

### 美学依据
`frontend-design`：原生控件是"通用 AI 味"的重灾区；自研 listbox 才能让下拉与整站字体/圆角/动效统一。`design-system`：下拉是高频复用件，必须沉淀为单一组件，杜绝三处各写一套。

## 4. 原文空格塌缩 `Ifeelsofortunate...`（问题 4）

### 根因（已确证）
`StreamLine.vue:11` 把整句 **逐字符** 拆成 span：
```vue
<span v-for="(part, index) in text.split('')" ... class="stream-token">{{ part }}</span>
```
而 `.stream-token { display:inline-block }`（main.css:1119）。空格字符被包进 `inline-block` 后宽度塌缩为 0 → `I` `feel` `so`… 全粘在一起。

### 改法（按词切分 + 保留空格）
逐"字符"的打字机效果是这个 bug 的来源，对**源文**而言逐词浮现既更易读、也天然保住空格：
```vue
<!-- StreamLine.vue -->
<script setup lang="ts">
import { computed } from "vue";
const props = defineProps<{ text: string; state?: string; strong?: boolean }>();
// 按空白切分并“保留”空白作为独立 token
const tokens = computed(() => props.text.split(/(\s+)/).filter((t) => t.length));
</script>

<template>
  <span class="stream-line" :class="{ partial: state === 'partial', strong }">
    <template v-for="(part, index) in tokens" :key="`${index}-${part}`">
      <!-- 空白原样输出，不加 inline-block，不参与动效 -->
      <span v-if="/^\s+$/.test(part)" class="stream-space">{{ part }}</span>
      <span v-else class="stream-token">{{ part }}</span>
    </template>
    <span v-if="state === 'partial'" class="stream-caret" aria-hidden="true">▍</span>
  </span>
</template>
```
```css
/* main.css */
.stream-line { display: inline; white-space: pre-wrap; }  /* 保留空格、允许换行 */
.stream-token { display: inline-block; animation: streamToken 260ms cubic-bezier(.16,1,.3,1) both; }
.stream-space { display: inline; white-space: pre; }       /* 空格不塌缩 */
```
> 中文译文那侧无空格不受影响；上面的正则切分对中英两者都安全（中文整段视作一个非空白 token，西文逐词）。

### 美学依据
`frontend-design`：动效服务可读性。逐词 stagger 比逐字符更克制、更高级，且根除空格 bug。

## 5. 工作台底栏按钮：砍重复 + 图标化（问题 5）

### 现状盘点（MediaPanel.vue:103-125 底栏 + WorkbenchView 顶栏）
| 按钮 | 出处 | 问题 |
|---|---|---|
| 设置 | MediaPanel:111 `@openSettings` | **与顶栏"同传设置"(WorkbenchView:91 `settingsOpen=true`) 完全重复** |
| 投送桌面 | MediaPanel:112 `@openDesktop` | 真实独立功能（deep-link 唤起桌面客户端悬浮窗），保留 |
| 展开字幕栏 | MediaPanel:115 | 与"悬浮字幕"显示模式（ModeSwitch）+ 顶栏切换重叠 |
| 暂停 / 继续 | MediaPanel:118-119 | **与原生 `<video controls>`(MediaPanel:62) 的播放/暂停重复** |
| 结束 | MediaPanel:120 | 保留（真实终止） |
| 新建同传 | MediaPanel:123 | report 态保留 |

### 逐条评估与决策
1. **"暂停"删掉。** 媒体源走的是 `<video controls>` / `<audio controls>`，原生播放器已有播放/暂停，且会话状态本就由 `@timeupdate → syncFixturePlayback` 跟随播放进度。再放一个 App 级"暂停"是重复且易混。→ **媒体源不再显示暂停/继续**；仅当未来出现"纯麦克风/系统音频、无媒体元素"的实时源时，再按需提供暂停（条件渲染），当前阶段可不做。
2. **"设置"删掉（底栏的那个）。** 与顶栏"同传设置"指向同一 `settingsOpen=true`。保留顶栏入口（更符合习惯），底栏不再重复。
3. **"悬浮"语义收敛为一个。** `悬浮字幕` 已经是 `displayModeOptions`（`["分区对照","逐句对照","悬浮字幕"]`，session.ts:53）里的显示模式（在右侧 ModeSwitch 选择）；底栏"展开字幕栏" + 顶栏切换是为"已处于悬浮模式、要退出/展开"服务。→ 底栏只保留**一个悬浮字幕开关**（图标 toggle）：非悬浮态点它进入悬浮、悬浮态点它展开字幕栏。顶栏那个条件链接随之去掉（统一到底栏 toggle）。
4. **"投送桌面"保留**（独立能力），图标化。
5. **"结束"保留**，图标化（危险色）。

### 改后底栏（图标 + tooltip，Lucide）
```
媒体进行中： [ ⧉ 投送桌面 ]  [ ⧈ 悬浮字幕 ]                         [ ◼ 结束 ]
report 态：                                                        [ ＋ 新建同传 ]
播放 / 暂停 → 交给原生播放器
```
图标映射（Lucide name）：
| 动作 | 图标 | aria-label / tooltip |
|---|---|---|
| 投送桌面 | `monitor-up` | 投送到桌面悬浮窗 |
| 悬浮字幕 toggle | `picture-in-picture-2` | 切换悬浮字幕 |
| 结束 | `square`（实心停止）| 结束同传 |
| 新建同传 | `plus` | 新建同传 |
| 顶栏·同传设置 | `sliders-horizontal` | 同传设置 |

> 按钮 = 图标 + `aria-label` + hover tooltip（`title` 或自绘 tooltip）。视觉沿用 `.stage-button`（main.css:843），但宽高收成正方 `36×36`、只放图标。**功能覆盖率不降反升**：原 6 个按钮（含 2 个重复 / 1 个与播放器重复）→ 3 个清晰职责。

### 美学依据
`frontend-design`「按钮越少越好、功能覆盖最重要」与用户诉求一致；统一图标语言 = `design-system`。

## 6. 悬浮字幕：收窄缩小 + 工具条图标化（问题 6）

### 6.1 尺寸（"高度和长度稍微小一些"）
**根因**：`.floating-caption-panel`（main.css:663）`left/right: clamp(16px,4vw,48px)` 让它几乎贴边满宽，`max-width:980px`、padding `12 14 16`、size-medium 字号 `clamp(18px,2.1vw,28px)`——整体偏大。
```css
/* :663 收窄、缩小、略微抬高 */
.floating-caption-panel {
  left: 50%;
  right: auto;
  transform: translateX(-50%) translateY(var(--cap-offset, 0));  /* 配合 JS 拖拽的 offsetY */
  bottom: clamp(24px, 6vh, 64px);
  width: min(92%, 680px);     /* was max-width:980 + 贴边 */
  gap: 8px;                   /* 10 → 8 */
  padding: 10px 14px 12px;    /* 收紧 */
}
.floating-caption-panel.size-small  { font-size: 15px; }
.floating-caption-panel.size-medium { font-size: clamp(16px, 1.8vw, 24px); }  /* was 18–28 */
.floating-caption-panel.size-large  { font-size: clamp(20px, 2.4vw, 32px); }  /* was 22–38 */
```
> 注意 `FloatingCaption.vue:83` 当前用 `transform: translateY(...)` 承载拖拽偏移；改成居中后，拖拽偏移改用 CSS 变量 `--cap-offset`（JS 写变量而非整个 transform），避免覆盖 `translateX(-50%)`。`onDragEnd` 里 `el.style.setProperty('--cap-offset', this.y + 'px')`。

### 6.2 工具条图标化（FloatingCaption.vue:85-100）
现状全是文字按钮：`仅译文/源+译`、`固定`、`小/中/大`、`透明度`、`×`。改为 Lucide 图标 + tooltip，并把"小中大"收成一个紧凑 segmented：
| 控件 | 现 | 改（Lucide） |
|---|---|---|
| 源+译 / 仅译文 | 文字 toggle | `languages`（双语）⇄ `type`（仅译文），图标 toggle |
| 固定 / 取消固定 | 文字 | `pin` / `pin-off` |
| 小 / 中 / 大 | 三个文字按钮 | 紧凑 segmented：`A−` `A` `A＋`（或 `type` 图标三档），高亮当前档 |
| 透明度 | 文字 + slider | `blinds` 图标 + 细 slider（hover 展开） |
| 关闭 | `×` | `x` |
| 状态点 | LIVE/延迟/重连 | 保留小圆点 + 文字（信息态，不图标化） |
```css
/* :715 工具条更紧凑 */
.floating-caption-toolbar { gap: 4px; font-size: 11px; }
.floating-caption-toolbar button {
  display: inline-grid; place-items: center;
  width: 26px; height: 26px; border-radius: 6px;
}
```

### 6.3 功能覆盖检查

## 8. 新增基建 A：统一图标系统（Lucide 内联 SVG）

> 用户确认：**Lucide 内联 SVG**（本环境 GitHub 直连受限，用 codeload zip 下载 `lucide` 源，取出所需 SVG 内联，不引入运行时依赖）。

### 落地方式
`components/icons/Icon.vue` —— 单组件 + name 注册表，全站唯一图标入口：
```vue
<script setup lang="ts">
const props = defineProps<{ name: string; size?: number }>();
// 仅内联本项目用到的 ~12 个图标的 path（从 lucide 源拷贝 path d）
const PATHS: Record<string, string> = {
  "chevron-down": "m6 9 6 6 6-6",
  "plus": "M5 12h14M12 5v14",
  "x": "M18 6 6 18M6 6l12 12",
  "sliders-horizontal": "M21 4h-7M10 4H3M21 12h-9M8 12H3M21 20h-5M12 20H3M14 2v4M8 10v4M16 18v4",
  // monitor-up / picture-in-picture-2 / square / pin / pin-off / languages / type / blinds
  // 复杂图标用整段内联其 SVG body，path d 以 lucide 官方为准
};
</script>
<template>
  <svg :width="size ?? 18" :height="size ?? 18" viewBox="0 0 24 24"
       fill="none" stroke="currentColor" stroke-width="2"
       stroke-linecap="round" stroke-linejoin="round" aria-hidden="true">
    <path :d="PATHS[name]" />
  </svg>
</template>
```
- `currentColor` 让图标继承按钮文字色，自动适配深/浅主题。
- 所需图标清单：`chevron-down`（下拉）、`sliders-horizontal`（设置）、`monitor-up`（投送桌面）、`picture-in-picture-2`（悬浮）、`square`（结束）、`plus`（新建）、`pin`/`pin-off`、`languages`/`type`（双语/仅译）、`blinds`（透明度）、`x`（关闭）。
- 复杂多段图标（如 `monitor-up`）用多个 `<path>` 或直接整段内联其 SVG body。

### 为何不直接 `npm i lucide-vue-next`
可作为备选（若 npm registry 可达更省事）；但用户已选"内联 SVG"，内联法零运行时依赖、可裁剪、最可控，符合 `frontend-design`「拥有你的资源」。

## 9. 新增基建 B：自研下拉 `SelectField.vue`

> 替换全部原生 `<select>`，是问题 3 的核心。

### 形态
```
┌─────────────────────────────┐        点击展开（GSAP 淡入 + y:-4→0）
│ 通用                     ⌄  │  ◀ 触发按钮：App 字体、圆角、--line 描边
└─────────────────────────────┘
   ┌─────────────────────────┐
   │ 通用                 ✓  │  ◀ 浮层 listbox：App 字体/配色
   │ 技术                    │     当前项打勾 + 高亮
   │ 商务                    │     hover 琥珀描边
   │ …                       │
   └─────────────────────────┘
```
### 契约（drop-in 替换现有 `v-model` 用法）
```ts
defineProps<{ modelValue: string; options: string[]; placeholder?: string }>();
defineEmits<{ "update:modelValue": [value: string] }>();
```
- 用法：`<SelectField v-model="form.domain" :options="domains" />`，与原 `<select v-model>` 等价。
- a11y：触发按钮 `role="button" aria-haspopup="listbox"`；浮层 `role="listbox"`，项 `role="option" :aria-selected`；键盘 ↑↓ 移动、Enter 选中、Esc 关闭、点击外部关闭。
- 动效：展开 `gsap.from(panel, { y:-4, opacity:0, duration:.14, ease:'power2.out' })`；遵守 `prefers-reduced-motion`。
- 样式 token：复用 `--line`/`--paper`/`--ink`/`--accent`，与 `.form-control` 视觉对齐但可控展开层。

### 替换点
