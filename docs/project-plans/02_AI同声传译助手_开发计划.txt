0. 前置约定（贯穿所有 PR）
----------------------------------------------------------------

· 合并后 main 始终可运行：每个 PR 都是可独立合入的增量，未接通的能力用

· 时间窗：以批次实际开始/截止为准（下表按 Day1=06-05 / Day2=06-06 /
  Day3=06-07 编排），所有 commit 时间戳须落在窗口内

1. P0 / P1 / P2 目标回顾
----------------------------------------------------------------
P0 最小可用：音频接入 → 流式 ASR → 整句翻译 → 双语字幕滚动（一条能跑的通路）
P1 核心创新（重点）：语义分块 → 增量翻译 + 三态字幕 → 回溯修正(L2) →
                     术语自学习全局回填(L3)  ← 直接落地"可见的自我纠错"
P2 体验加分：延迟-准确度档位 → 供应商热切换/兜底 → 历史导出 →
            标签页/系统音频来源 → 中文配音

3. 逐 PR 详情（可直接粘进 PR 描述）
----------------------------------------------------------------
PR1 chore/scaffold
  功能描述：建立 frontend(Vue3+Vite+TS+Tailwind+Pinia) 与 backend(FastAPI)
            目录骨架，跑起空壳页面与健康检查接口。
  实现思路：pnpm 建前端、uv 建后端；约定目录(见技术栈文档第七节)；README 占位。
  测试方式：pnpm dev 打开空页面；uvicorn 启动后 /health 返回 200。
PR2 feat/ws-channel
  功能描述：建立浏览器↔后端的 WebSocket 通道，定义统一事件协议
            {type:partial|final|delta|done|error, seq, ts, payload}。
  实现思路：FastAPI websocket 路由；前端封装 ws 客户端；先用回显验证。
  测试方式：前端发测试帧，后端回显；断开重连正常。
PR3 feat/audio-capture
  功能描述：前端采集音频并推流：内置播放器(MediaElementSource) + AudioWorklet
            取 PCM、48k→16k 单声道、Int16 二进制帧经 ws 上行。
  实现思路：AudioWorklet 处理 + 重采样；可视化音量条确认有流。
  测试方式：播放样例音频，后端收到稳定 PCM 帧（打印帧率/字节数）。
PR4 feat/ai-gateway
  功能描述：统一 AI 接入层骨架：定义 ASR/Translate 能力接口、适配器接口、
            providers.yaml 路由配置；先注册一个 mock 适配器。
  实现思路：抽象 Capability + Adapter + Router(选型/降级)；配置驱动。
  测试方式：用 mock 适配器跑通"假识别/假翻译"，验证路由可切换。
PR5 feat/streaming-asr
  功能描述：接入真实流式 ASR(先一家)，输出带时间戳/置信度的 partial/final，
            前端显示实时英文字幕。
  实现思路：实现首个 ASR 适配器；将 partial/final 经 ws 下发。
  测试方式：放英文音频，英文字幕实时滚动，final 修订 partial。
PR6 feat/sentence-translation
  功能描述：对 final 文本整句翻译成中文，双语字幕(上原文/下中文)滚动。
            ← P0 最小可用闭环完成。
  实现思路：实现首个 Translate 适配器；整句触发翻译；双语字幕组件。
  测试方式：英文演讲→中文字幕可读、能跟上；main 此时可独立演示。

PR7 feat/vad-chunking
  功能描述：引入 Silero VAD + 语义分块器，按子句边界 + 最大等待阈值切翻译单元。
  实现思路：本地 VAD 端点检测；标点/停顿启发式；阈值可配。
  测试方式：对比有/无分块的触发时机；阈值生效（超时强制出译）。
PR8 feat/incremental-translation
  功能描述：不等整句，按语义块抢先翻译，产出"临时"译文（降低延迟）。
  实现思路：基于分块的增量翻译调用；维护片段 id 与上下文窗口。
  测试方式：译文随说话推进而提前出现，延迟下降。
PR9 feat/three-state-subtitle
  功能描述：字幕三态(临时/稳定/已修正)渲染，片段稳定 id + 原地平滑更新。
  实现思路：Pinia 维护 segment 状态；partial/final 与翻译单元对齐；过渡动画。
  测试方式：临时态(灰/斜)→稳定态切换可见且不整屏重刷。
PR10 feat/retrospective-correction
  功能描述：翻译层回溯修正(L2)：新句揭示前句译错时联合重译并回填"已修正"态。
  实现思路：上下文窗口联合校对；仅在置信度实质提升时回改(滞后阈值防抖)。
  测试方式：构造含歧义/长难句样例，前句译文被后文修正且不乱跳。
PR11 feat/glossary-backfill
  功能描述：术语自学习(L3)：识别专名/术语，确定规范译名后全局回填+后续锁定。
  实现思路：流式实体识别 + 术语表；对已显示片段追溯式一致编辑；支持术语包。
  测试方式：人名先错后被全局统一更正；同一术语全程一致。
PR12 feat/two-tier-translation
  功能描述：两层翻译——快模型做临时态抢跑、强模型做回溯修正与一致性。
  实现思路：接入层按"临时/稳定"分别路由快/强模型；与三态、L2/L3 协同。
  测试方式：临时态延迟低、稳定态质量高；切换模型行为正确。

PR13 feat/latency-accuracy
  功能描述：延迟-准确度档位(快/平衡/准确)，调节块大小与最大等待阈值。
  测试方式：同段音频切档位，抢跑量/稳定度按预期变化。
PR14 feat/provider-failover
  功能描述：接入第二家供应商 + 热切换；云端超时降级到本地 faster-whisper。
  测试方式：手动切换供应商正常；断网/超时自动降级不中断。
PR15 feat/history-export
  功能描述：整场字幕历史回看/搜索 + 导出双语 srt/txt。
  测试方式：回看历史、导出文件按时间轴正确。
PR16 feat/getdisplaymedia (机动)
  功能描述：新增 getDisplayMedia 标签页/窗口音频来源，适配真实网页视频/会议。
  测试方式：共享某标签页音频→字幕正常。
PR17 feat/tts-dubbing (机动)
  功能描述：可选中文配音，仅朗读"稳定态"句子，默认关、可降低原声音量。
  测试方式：开启后朗读稳定句、不打断字幕修正。
PR18 docs/readme-and-polish
  功能描述：README 列明全部第三方依赖与运行方式；自动滚动/断线重连等体验打磨；
            准备 demo 数据集。
  测试方式：照 README 从零跑通；回归 P0/P1 关键路径。
