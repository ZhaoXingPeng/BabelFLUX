AI 小说转剧本工具 - 初步方案
版本：v0.1
日期：2026-06-05

一、项目定位
本项目面向小说作者、编剧和内容团队，帮助他们将 3 个章节以上的小说文本转换为结构化剧本初稿。产品重点是降低改编启动成本，而不是一次性生成最终可拍摄剧本。输出应采用 YAML 格式，便于人类编辑、版本管理和后续工具处理。

二、核心目标
1. 支持导入至少 3 个章节的小说文本。
2. 自动识别人物、地点、时间线、关键事件和章节结构。
3. 将小说内容改编为结构化剧本 YAML。
4. 保留原作核心情节，同时将叙述性文字转换为场景、动作和对白。
5. 提供可编辑、可追踪、可再次生成的剧本初稿。
6. 额外提供 YAML Schema 文档，明确字段定义和设计原因。

三、MVP 范围
1. 支持 TXT 或 Markdown 小说文本导入。
2. 支持按章节解析，至少处理 3 个章节。
3. 自动生成角色表、地点表、故事梗概、分场列表和对白动作。
4. 输出单个 YAML 文件。
5. 提供基础校验：YAML 格式合法、必填字段完整、scene_id 唯一、角色引用存在。
6. 支持用户指定改编方向，例如影视剧本、短剧剧本、广播剧剧本。MVP 建议先聚焦影视剧本。

四、核心用户流程
1. 用户上传小说文本或粘贴章节内容。
2. 系统解析章节边界，并生成章节摘要。
3. 系统抽取人物、地点、关键事件、冲突关系和时间线。
4. 用户确认或简单编辑角色名、人物关系和改编目标。
5. 系统生成剧本结构，包括幕、场、场景描述、动作、对白和转场。
6. 系统输出 YAML，并显示结构化预览。
7. 用户可编辑 YAML 或局部重新生成某一场。

五、系统架构
1. 文本导入层
负责文件上传、编码识别、章节切分、清洗空行和去除无关符号。

2. 小说理解层
负责章节摘要、人物识别、地点识别、事件抽取、情绪变化、叙事视角和时间顺序判断。

3. 改编规划层
将小说章节映射为剧本幕和场，决定哪些内容保留、压缩、合并或改写。

4. 剧本生成层
按 Schema 生成 YAML，包括 scene、action、dialogue、transition、note 等结构。

5. 校验与修复层
对 YAML 进行格式校验、字段校验、引用校验和长度校验。发现问题时自动修复或提示用户。

6. 编辑与再生成层
允许用户编辑角色、场景、对白，并对指定场景进行局部重写。

六、改编策略
1. 叙述转画面
将心理描写和背景叙述尽量改写成可拍摄动作、环境细节或对白，不保留大段说明。

2. 章节转场景
一个小说章节可拆分为多个剧本场景。拆分依据包括地点变化、时间变化、人物目标变化和冲突节点变化。

3. 人物一致性
生成前先建立角色表，后续所有对白和动作引用角色 id，避免同一人物多种名称混用。

4. 保留关键冲突
优先保留推动主线、揭示人物关系和改变角色目标的事件。弱情节可压缩为过场或省略。

5. 输出可编辑
YAML 不追求文学化排版，而是追求字段清晰、结构稳定、便于二次编辑。

七、YAML 输出结构建议
顶层包括 project、source、adaptation、characters、locations、acts、validation_notes。

1. project
记录剧本标题、版本、目标媒介、语言和生成时间。

2. source
记录原小说章节范围、原文摘要和改编保留原则。

3. adaptation
记录改编风格、节奏、目标时长、受众和叙事视角。

4. characters
记录角色 id、姓名、别名、人物简介、目标、关系和首次出现章节。

5. locations
记录地点 id、名称、类型、视觉描述和相关场景。

6. acts
记录幕结构，每一幕下包含多个 scenes。

7. scenes
记录场景 id、标题、时间、地点、参与人物、场景目标、冲突、节拍和内容块。

8. content blocks
内容块支持 action、dialogue、parenthetical、transition、note 等类型。

八、评价指标
1. 结构合法性：YAML 可解析，字段完整，引用一致。
2. 情节保真度：是否保留原文关键事件和人物动机。
3. 剧本可用性：是否符合场景、动作、对白的剧本表达习惯。
4. 改编效率：用户从小说输入到拿到初稿所需时间。
5. 可编辑性：用户能否快速定位并修改某个角色、场景或对白。

九、开发里程碑
第一阶段：完成小说导入、章节切分、章节摘要。
第二阶段：完成人物、地点、事件抽取和改编规划。
第三阶段：实现 YAML 剧本生成和 Schema 校验。
第四阶段：支持可视化编辑、局部重写和版本对比。

十、主要风险与应对
1. 长文本上下文过长
应对：采用分章节摘要、全局记忆表和分场生成策略，不一次性处理全文。

2. 人物名称混乱
应对：先生成角色表和别名表，后续生成必须引用角色 id。

3. 输出不像剧本
应对：在生成层强制使用 action、dialogue、scene_heading 等剧本字段，减少叙述性段落。

4. YAML 格式不稳定
应对：使用 Schema 校验和自动修复流程，必要时要求模型先生成 JSON 再转换为 YAML。

十一、初步结论
该项目的核心竞争力在于“长文本理解 + 改编规划 + 稳定结构化输出”。首版应先保证 YAML 结构稳定和改编逻辑清晰，再增强剧本艺术性和细粒度编辑体验。
