# 字幕配对聚合性能实验

## 目标

`transcriptPairs` 原实现先用 `includes` 去重，再对每个 `segmentId` 调用两次
`find`。当源文和译文各有 n 个段时，每次字幕事件更新都要重复扫描数组；本次
将聚合逻辑提取为纯函数，并用 `Map` 保存每个 ID 的源文/译文引用，目标复杂度
从 O(n²) 降为 O(n)。

## 可复现实验

- 命令：`cd frontend && npm run bench:transcript`
- 数据：2,000 个源文段 + 2,000 个同 ID 译文段，固定时间戳和文本
- 基线：`includes` 去重 + 每个 ID 两次 `find`
- 优化：单次 `Map` 聚合 + 一次结果映射
- 环境：Node `v22.17.0`、Vitest `4.1.8`（Windows 工作区）

## 结果

| 实现 | ops/s | 平均耗时 |
| --- | ---: | ---: |
| 基线 | 33.7813 | 29.6022 ms |
| Map 聚合 | 3,611.68 | 0.2769 ms |

本次固定数据下 Map 实现约 **106.91 倍**。该数字只代表上述数据规模和本机
运行结果，不等同于真实用户会话的端到端延迟；线上收益仍需结合实际会话埋点复核。

## 行为验证

- 源文 ID 顺序优先，译文独有 ID 追加在末尾。
- 同一 ID 的源文/译文保持配对，修订元数据继续透传。
- 会话中无字幕返回空数组，首屏预览仍返回示例数据。
- 无译文的非当前源文继续过滤，避免改变字幕呈现行为。
