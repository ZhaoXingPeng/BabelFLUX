AI 同声传译助手 - 流程与布局设计
版本：v0.1
日期：2026-06-05
状态：流程设计稿

一、文档目标

本文档用于明确 AI 同声传译助手下一阶段的产品流程与页面布局，作为后续 UI
设计、前端组件拆分、后端会话接口扩展和 PR 拆分的依据。

本 PR 只做流程与布局设计，不实现代码，不调整历史 PR，不处理已有 main 分支中的
工程问题。后续功能开发继续遵循“一个 PR 只做一件事”的规则。

二、设计原则

1. 双入口，单底座
   最外层只提供“快速同传”和“悬浮字幕”两个入口。两个入口使用同一套会话、
   音源、语言、模型、字幕事件和结束报告能力，只是使用场景和界面密度不同。

2. 先 Web 可演示，再桌面增强
   Web 形态可以实现浏览器内悬浮字幕、标签页音频、屏幕共享音频和文件同传。
   纯 Web 页面不能稳定覆盖浏览器外的其他应用窗口。真正浮在 PPT、会议软件、
   本地播放器等其他应用上方，需要 Tauri、Electron 或原生桌面端提供系统级
   悬浮窗和系统音频采集能力。

3. 运行中少打扰，结束后可复盘
   实时阶段优先降低操作干扰，突出当前字幕和翻译。结束后再提供完整转写、
   翻译、修正记录、术语命中和导出能力。

4. 状态明确
   会话必须清楚区分未开始、连接中、运行中、暂停、结束确认、已结束和错误状态，
   避免用户不知道系统是否还在录音、识别或计费。

三、最外层信息架构

首页保留两个主入口：

1. 快速同传
   面向完整会议、视频、音频、URL、直播、网课等场景。用户需要配置任务、管理
   声源、查看视频或音频、对照转写和翻译，并在结束后导出记录。

2. 悬浮字幕
   面向轻量场景。用户已经在别处观看内容或参加会议，只需要一条低干扰字幕层。
   重点是快速开始、可拖动、可锁定、可调整字号、可暂停和结束。

两个入口最终都创建一个 Session：

会话字段：
1. session_id：会话 ID。
2. name：会话名称。
3. scenario：quick_interpretation 或 floating_subtitle。
4. domain：专业领域。
5. source_language：源语言，可自动检测。
6. target_language：目标语言。
7. model_profile：模型档位或供应商。
8. input_source：输入声源。
9. output_mode：字幕、双语对照、语音播报、导出记录等。
10. status：idle、connecting、running、paused、ending、finished、error。

四、悬浮字幕流程

4.1 入口前置设置

用户点击“悬浮字幕”后，进入轻量设置面板。

设置项：
1. 模型选择
   - 智能默认：系统根据延迟和质量自动选择。
   - 快速低延迟：优先跟上内容节奏。
   - 高准确：允许更高延迟，优先翻译质量。
   - 自定义：后续开放指定供应商和参数。

2. 语言选择
   - 源语言：自动检测、英语、日语、韩语、中文等。
   - 目标语言：默认中文，可切换为英文或其他语言。

3. 专业领域
   - 通用、技术、商务、教育、医疗、法律、自定义术语表。

4. 声源
   - 麦克风：Web MVP 可做，适合外放或线下场景兜底。
   - 浏览器标签页音频：Web 优先支持，适合网课、网页视频。
   - 屏幕或窗口音频：取决于浏览器权限和平台能力。
   - 系统音频：桌面端能力，Web 不承诺。

5. 字幕样式
   - 单语或双语。
   - 字号。
   - 透明度。
   - 显示行数。
   - 位置：底部居中、顶部居中、自由拖动。

底部主按钮：
开始使用。

4.2 开始流程

流程：
1. 用户点击“开始使用”。
2. 系统请求声源权限。
3. 权限通过后进入连接中状态。
4. 后端创建会话并建立 WebSocket。
5. 检测到音频后进入运行中状态。
6. 字幕窗开始显示原文和译文。

异常：
1. 用户拒绝权限：提示重新选择声源或改用麦克风。
2. 未检测到声音：保留悬浮窗，提示“未检测到音频输入”。
3. WebSocket 断开：显示重连状态，并允许用户结束。

4.3 悬浮字幕布局

默认布局：

顶部右侧操作区：
1. 锁定：锁定位置和尺寸，避免误拖动。
2. 字号减小。
3. 字号放大。
4. 透明度。
5. 设置：打开语言、模型、样式快速设置。
6. 关闭：触发结束确认，不直接丢弃会话。

主体字幕区：
1. 上一句弱化显示。
2. 当前句高亮显示。
3. 译文优先显示，原文可作为较小文字显示。
4. 被修正内容短暂高亮，并在报告中保留修正记录。

底部中间控制区：
1. 未开始：开始使用。
2. 运行中：暂停、结束。
3. 暂停中：继续、结束。

4.4 结束确认

用户点击关闭或结束时，不直接结束会话，而是打开确认层。

确认层内容：
标题：结束本次字幕？
说明：结束后将停止识别和翻译，并生成本次字幕记录。
按钮：
1. 暂不结束：返回悬浮字幕运行或暂停状态。
2. 结束会议：停止音频处理，关闭悬浮字幕，进入结果页。

4.5 结束后结果页

展示内容：
1. 会话名称和时长。
2. 源语言和目标语言。
3. 完整转写。
4. 完整翻译。
5. 修正记录。
6. 导出入口：TXT、SRT、VTT、Markdown。
7. 操作入口：再次开启悬浮字幕、进入快速同传工作台查看完整记录。

五、快速同传流程

5.1 入口设置

用户点击“快速同传”后进入完整任务设置页。

任务设置字段：
1. 会话名称
   示例：OpenAI 发布会同传、国际会议技术分享、英语网课第 1 讲。

2. 专业领域
   通用、技术、金融、医疗、法律、教育、自定义术语表。

3. 转换语言
   - 源语言：自动检测、英语、日语、韩语、中文等。
   - 目标语言：中文、英文或其他语言。

4. 模型选择
   - 智能默认。
   - 低延迟。
   - 高准确。
   - 成本优先。
   - 指定供应商。

5. 输入声源
   - 视频文件：mp4、mov、webm。
   - 音频文件：mp3、wav、m4a、aac。
   - URL：网页视频、音频链接、直播链接。
   - 麦克风。
   - 浏览器标签页音频。
   - 屏幕或窗口共享音频。
   - 系统音频：桌面端增强能力。

底部主按钮：
开始同传。

5.2 声源选择规则

1. 本地视频或音频
   优先在 Web MVP 支持。用户上传后在左侧播放器中播放，系统同步处理音轨。

2. URL
   先作为输入来源记录。可直接播放的 URL 嵌入播放器；不可直接解析的 URL 提示
   用户改用“浏览器标签页音频”方式采集。

3. 浏览器标签页音频
   适合网页视频、网课和直播。需要用户选择共享标签页并勾选音频。

4. 屏幕或窗口音频
   能力取决于浏览器和操作系统。作为增强项，不作为 Web MVP 的唯一核心路径。

5. 麦克风
   作为兜底输入，适合外放音频或线下讲座。

6. 系统音频
   纯 Web 不承诺。桌面端通过 Tauri 或 Electron 承接。

六、快速同传工作台布局

6.1 默认布局

整体采用清爽的左右布局。

顶部状态栏：
1. 会话名称。
2. 源语言到目标语言。
3. 模型档位。
4. 运行状态。
5. 计时。
6. 暂停、继续、结束。

左侧主区域：
默认展示视频、音频播放器或声源状态。占屏幕主要宽度，用于让用户确认当前处理
的内容和进度。

右侧同传区域：
展示实时转写、翻译、修正提示和显示模式切换。

底部状态区：
展示音量电平、延迟、连接状态、已处理时长和导出状态。

6.2 左侧四分区能力

左侧区域最多支持田字格四块。默认不是同时铺满，而是根据模式逐步展开。

四块建议：
1. 左上：视频或音频播放器。
2. 右上：源文实时转写。
3. 左下：译文实时输出。
4. 右下：修正记录、术语命中、会话摘要。

常用布局：
1. 默认布局：左侧播放器，右侧同传。
2. 分析布局：左侧四分区，右侧显示模式和详情。
3. 复盘布局：播放器缩小，逐句对照和修正记录放大。

6.3 右侧显示模式

右侧同传区域提供以下模式：

1. 分区对照
   原文和译文分成上下或左右两个区域，适合会议复盘和审阅。

2. 转写翻译
   按时间流展示，先展示源文，再展示译文，适合实时观察处理过程。

3. 分区显示
   将视频、转写、翻译、修正、术语等内容拆为多个面板，适合专业用户监控质量。

4. 逐句对照
   每一句都显示原文和译文，适合阅读和导出。

5. 按句分段
   严格一句一段，避免长文本堆积，适合字幕导出。

6. 语意清晰
   按语义块聚合和改写，让译文更符合中文表达。该模式允许稍高延迟，适合高准确
   场景。

6.4 字幕状态

实时内容至少包含四种状态：

1. partial
   临时识别结果，浅色显示，可被后续覆盖。

2. final
   已确认源文，正常显示。

3. translated
   已翻译文本，作为用户主要阅读内容。

4. revised
   被后文上下文修正的文本，短暂高亮，并在修正记录中保留前后对比。

七、暂停和结束流程

7.1 暂停

用户点击暂停后：
1. 停止接收或处理新音频。
2. 保留当前字幕和翻译结果。
3. 页面状态变为暂停中。
4. 主按钮变为继续。

7.2 继续

用户点击继续后：
1. 恢复音频处理。
2. 状态变为运行中。
3. 新字幕继续追加。

7.3 结束

用户点击结束后进入确认层。

确认层内容：
标题：结束本次同传？
说明：结束后将停止音频处理，并生成转写、翻译和修正记录。
按钮：
1. 暂不结束。
2. 结束会议。

结束后进入报告页。

八、报告页流程

报告页用于复盘和导出。

内容结构：
1. 会话概览：名称、时长、语言方向、模型、声源。
2. 完整转写：按时间顺序展示源文。
3. 完整译文：按时间顺序展示译文。
4. 逐句对照：源文和译文绑定显示。
5. 修正记录：展示 before、after、reason、confidence。
6. 术语命中：展示术语、翻译、命中次数。
7. 导出：TXT、SRT、VTT、Markdown。

九、页面与组件拆分建议

页面：
1. HomePage：双入口。
2. FloatingSubtitleSetupPage：悬浮字幕设置。
3. FloatingSubtitleWindow：悬浮字幕运行窗。
4. QuickInterpretationSetupPage：快速同传设置。
5. InterpretationWorkspacePage：快速同传工作台。
6. SessionReportPage：结束报告。

核心组件：
1. SessionHeader：会话顶部状态栏。
2. SourceSelector：声源选择器。
3. LanguageSelector：语言选择器。
4. ModelProfileSelector：模型档位选择器。
5. DomainSelector：专业领域选择器。
6. MediaStage：视频或音频展示区。
7. SubtitleStream：实时字幕流。
8. ParallelTranscriptView：逐句对照视图。
9. RevisionTimeline：修正记录。
10. FloatingSubtitleControls：悬浮字幕控制区。
11. EndSessionDialog：结束确认。
12. ExportPanel：导出面板。

十、MVP 到增强路径

MVP 优先级：
1. 首页双入口。
2. 快速同传设置页。
3. 本地音视频和麦克风输入。
4. 左右工作台。
5. mock 或真实 provider 的实时字幕事件流。
6. 结束确认和报告页。
7. 浏览器内悬浮字幕。

增强优先级：
1. 浏览器标签页音频。
2. URL 输入。
3. 多布局切换。
4. 语意清晰模式。
5. 修正记录可视化。
6. Document Picture-in-Picture 悬浮窗。

桌面端优先级：
1. 系统级悬浮字幕。
2. 系统音频采集。
3. 锁定、置顶、穿透点击。
4. 覆盖其他应用窗口。

十一、后续 PR 拆分建议

1. docs: 补充流程与布局设计
   本文档，明确产品流程和布局。

2. feat: 新增首页双入口
   实现快速同传和悬浮字幕入口，不接真实音频。

3. feat: 新增快速同传设置页
   实现会话名称、专业领域、语言、模型、声源选择。

4. feat: 新增快速同传工作台布局
   实现左右布局、媒体区域、同传区域和基础状态栏。

5. feat: 新增浏览器内悬浮字幕
   实现浏览器页面内的可拖动字幕层和运行控制。

6. feat: 新增结束确认与报告页
   实现暂不结束、结束会议、转写翻译记录展示和导出入口。

十二、验收标准

1. 用户能理解两个入口分别解决什么问题。
2. 悬浮字幕从设置、开始、暂停、结束到报告的流程完整。
3. 快速同传从任务设置、声源选择、工作台到报告的流程完整。
4. Web 与桌面能力边界清楚，不承诺纯 Web 无法稳定实现的系统级能力。
5. 后续页面和组件拆分可以直接映射为 PR。
