## 1. 一句话定位（开场用）

> **"BabelFlux 是一套能'自我纠错'的个人实时同声传译系统：把任意外语音频流实时变成可读、会自动改对、可留存的双语字幕——不绑定会议平台，浏览器即开，还能甩到桌面全局悬浮窗。"**

定位锚点（对标调研结论）：
- 大厂（讯飞/字节）拼的是**延迟和大模型**；我们拼的是**产品形态 + 体验工程 + 纠错机制**。
- 行业 90% 都是"三段级联"架构——**我们也是级联，但在级联之上多做了一层别人没产品化的"在线纠偏"**。

## 4. 主题逐个的技术解构（每个含：应用价值 / 技术实现 file:line / 诚实差距 / Q&A）

### 主题一 ⭐ 会"自我纠错"的同传 ↔ 双层纠偏引擎

**应用价值（讲给人听）**
- 机器同传最大的尴尬是"说错就错到底"：把技术语境的 *Transformer* 译成"变压器"、把 *50 毫秒* 听成"50 秒"，观众只能将错就错。
- BabelFlux 在**传译进行中**就回看前几句，发现明确错误**立刻把已经显示的译文改对**（前端琥珀高亮）；会议结束后再用更强的模型**通读全场**做一次全局校正、统一术语、生成摘要。
- **这是竞品几乎没有产品化的能力**——大厂在拼"延迟/边听边说"，没人主打"输出后还能回头改对"。

**技术解构（讲给工程师听）**
- **两层分工**（性能/成本/质量分级，呼应行业"级联可热插拔"共识）：
  - 实时层 `RealtimeReviser`（`backend/app/services/revision.py`）：低延迟模型 `qwen-flash`，窗口 4 句（`revision.py:73`），**限速 6 次/分钟**（`revision.py:92`），置信度阈值 0.62（`revision.py:75`），**只改"非最后一句"**（`revision.py:110`，最新句还在变不能动），后台 `asyncio` 任务**非阻塞**主字幕流（`pipeline.py:969-976`）。
  - 会后层 `generate_session_report`（`backend/app/services/report.py`）：强模型 `qwen-plus` 通读全场，带**超时**（`report.py:87`）、**5 态降级**（completed/partial/fallback/timeout/skipped，`report.py:95-119`）、**覆盖率校验**（`report.py:95`）、**防御性解析**（LLM 偶发返回非 dict 时 `isinstance` 过滤而非崩溃，`report.py:121-132`）。
- **Prompt 工程的关键洞察（强烈建议现场讲，最显功力）**：最初 prompt 只强调"保守"，真实 qwen-flash **对明显错误也按兵不动 → 0 触发**；重平衡为"**不做风格润色 + 显式列出应纠的错误类别与示例**"（`revision.py:40-61`）后，**明确错误可靠触发（conf≈0.98），干净句零误纠**。这是"调真实模型调出来的经验"，不是拍脑袋。
- **六大领域差异化**：通用/技术/商务/教育/医疗/法律各有纠偏关注点（`revision.py:26-33`），实时层与会后层共享同一套领域知识。
- **先改字幕、再发事件**：`_apply_revision` 先下发 revised 译文段（高亮）再发 `revision_event` 供时间线展示（`pipeline.py:1009-1021`）。

**诚实差距 #3（主动讲）**：每句完成都 spawn 一个复核任务，窗口重叠时同一句可能被两个任务先后改写、无 `status=="revised"` 幂等校验（`pipeline.py:986`）→ 偶发"改了又改"。**我们已定位，修法是对同一 segment 加版本号/串行化。** —— 这句话本身就是加分项。

**Q&A 预案**
- *Q：实时纠偏会不会把对的改错（误纠）？* A：三重保险——置信度阈值 0.62 过滤、只改有把握的错误类别、`after==before` 直接丢弃（`revision.py:157`）；真实联调验证干净句零误纠。
- *Q：纠偏会拖慢字幕吗？* A：不会，复核是后台任务，不在主字幕发射路径上（`pipeline.py:973`）；还有 6 次/分钟限速防刷屏。
- *Q：为什么要两个模型而不是一个？* A：实时要"快"（qwen-flash 低延迟、跨句轻量），会后要"准"（qwen-plus 全局上下文）。延迟与质量不可兼得，所以分层——这正是行业级联架构的精神。

### 主题二 ⭐ 任意音源 · 零部署 · 桌面全局悬浮 ↔ 采集管线 + Tauri 原生 + handoff

**应用价值（讲给人听）**
- 个人场景里"音频"五花八门：浏览器里的网课、本地视频文件、YouTube/B 站标签页、整个系统的声音、线下讲座的麦克风。BabelFlux **七种音源一个入口**，且**纯浏览器零安装**就能用。
- 想要"字幕浮在任何窗口之上"（边看 PPT 边看字幕）时，一键甩到**桌面透明悬浮窗**，全局置顶、可拖、可调透明度。
- 覆盖的是竞品薄弱的**个人长尾**——竞品要么是会议 SaaS、要么是企业活动平台、要么是硬件。

**技术解构（讲给工程师听）**
- **统一采集管线**（Web 与桌面共用，`frontend/src/composables/useAudioCapture.ts`）：
  - `new AudioContext({ sampleRate: 16000 })` 让**浏览器原生重采样**到模型要的 16k，规避手写重采样误差（`useAudioCapture.ts:219`）。
  - **AudioWorklet 跑在主线程外**，processor 用 **Blob URL 注入**——前端与桌面 Vite 工程都免额外构建配置（`useAudioCapture.ts:16-33`）。
  - 接一个**静音 gain → destination**：既保证 worklet 在所有浏览器都被调度，又不把采集音频外放造成啸叫（`useAudioCapture.ts:252-256`）。
  - **对症权限提示** `describeMediaError`：把 `NotAllowed/NotFound/NotReadable/Abort` 翻成可操作的中文指引（`useAudioCapture.ts:148-177`）。
  - **上传文件走 `startMediaElementAudioCapture`**：直接从**正在播放的 `<video>` 元素**采集音频，"看到/听到的就是模型输入"，**避免前端播 blob、后端另起 ffmpeg 解码的双时钟问题**（`useAudioCapture.ts:286-386`）。
- **Tauri 桌面原生能力**（`desktop/src-tauri/src/`）：
  - **WebView2 宿主侧放行麦克风**（`main.rs:32-61`）：透明置顶窗口上 WebView2 的权限气泡几乎无法点击，导致麦克风 `getUserMedia` 静默卡死；在宿主侧注册 `PermissionRequested` 对麦克风/摄像头直接 `ALLOW`——符合 Windows/WebView2"由宿主决定媒体权限"的最佳实践，用户选麦克风**一次成功、免弹窗**。
  - **系统音频走原生 WASAPI loopback**（`audio_capture.rs`）：独立线程抓默认播放设备、16k 单声道 40ms 分帧、base64 经 Tauri 事件回传——**完全绕开 WebView2，本就无需授权**。
  - 透明无边框置顶 + 原生拖拽区（`native_drag.rs`、`main.rs:90-97`）。
- **Web→桌面 deep-link 接管（handoff，最能讲架构的一段）**：
  - Web 端 `openDesktopFloating`（`session.ts:982`）调后端签发**一次性 handoff token**（`backend/app/services/handoff.py`：TTL 300s、单次使用、不带凭据）→ 拼 `lingosync://floating/start?...&token=` deep-link。
  - **乐观唤起 + 超时回退**：`armDesktopLaunchFallback`（`session.ts:950`）用 `visibilitychange/blur` 探测 App 是否真的起来了，2.5s 没起来就弹下载提示——解决"点了没反应"的体验黑洞。
  - 桌面端 `claimHandoffToken`（`desktop/src/api/sessionBridge.ts:18`）兑换出 `ws_token` → 连 WS，后端 `_serve_handoff_socket`（`ws.py:187`）从**事件 hub 重放历史 + 转发实时事件**（`session_events.py`）→ 桌面**无缝接管** Web 正在跑的会话。

**诚实差距 #2（主动讲）**：所谓"客户端时钟双向同步"其实是**单向只读观测**——后端权威时钟按喂入字节累加（`pipeline.py:210`），客户端 `playbackMs` 只用来发一条 lag 状态提示（`pipeline.py:1074`），**没有回写时间码**；丢帧下会漂移。**真双向要把 `playbackMs` 用于校正段落时间码——这是我们明确的下一步。**

**Q&A 预案**
- *Q：浏览器为什么能抓系统/标签页音频？* A：`getDisplayMedia` + 按音源种类定制约束（`useAudioCapture.ts:80-119`），并校验真的拿到了音频轨（`validateDisplayStream`）。
- *Q：handoff token 安全吗？* A：一次性、300s 过期、单次使用、不携带任何模型凭据（`handoff.py`），WS 侧二次校验（`ws.py:49`）。**这是全项目鉴权做得最好的一处**（反衬主路径待补，见诚实差距 #1）。
- *Q：为什么用 Tauri 不用 Electron？* A：复用同一套 Vue 前端，包体更小，且能直接写 Rust 原生（WASAPI loopback、PermissionRequested）做浏览器做不到的系统级能力。

### 主题三 ⭐ 把"机器同传的脏流"变可读可信可留存 ↔ 流对齐 + 柔和化 + 可降级

**应用价值（讲给人听）**
- 机器同传的原始输出是"脏"的：识别 partial 反复跳变、译文比原文滞后 2~3 秒、断句和原文对不齐、字幕一顿一闪。**讯飞自己都把"消除碎片化割裂感"当卖点**——可见这是公认难点。
- BabelFlux 让字幕**平滑滚出、原文译文对齐、纠偏柔和高亮**，结束后一键导出**双语终稿 + 校正记录 + 摘要**（TXT/SRT/MD/JSON），把"听过就忘"变成"可留存可复用"。
- 而且**模型挂了也能演示**——可降级保证链路永远能跑。

**技术解构（讲给工程师听）**
- **流对齐引擎**（`backend/app/services/pipeline.py`，全项目最硬的一块）：
  - **FIFO 译文绑定**（`pipeline.py:317-337`）：源用输入 `item_id` 归段、译文用 `response_id` 绑定到**最早一个尚未配译文的段**——抵抗"译文比源滞后 ~2.8s、跨越了下一句 `speech_started`"造成的错配。
  - **ASR partial 快照 vs 增量智能合并**（`pipeline.py:435-470`）：DashScope 的 partial 有时是全量快照、有时是增量碎片，做前缀/重叠判定与**重复塌缩**（`_collapse_source_repetition`），避免字幕从完整句回退成尾巴碎句。
  - **句级双语对齐**（`pipeline.py:652-719`）：只在原文/译文**句数相等**时才按句拆分配对，避免中英断句不齐造成的错位配对。
- **字幕柔和化（纯展示层，不动时序/不降效率）**：
  - `StreamLine.vue`：旧实现 `split(/\s+/)` 把无空格中文整句当一个 token，每次 partial 变化→key 变→Vue 重挂载→整行重放动画=闪。改为**CJK 按字、拉丁按词分词 + 索引作 key**，已显单元原地复用、只有新增尾部淡入（`StreamLine.vue:18-28`）。
  - `useStickyFollow.ts`：**合并去抖**——目标位移 < 28px 跳过，累计超阈值或换句才发新补间，消除逐字滚动抖动（`useStickyFollow.ts:19,39`）；尊重 `prefers-reduced-motion`。
- **延迟自适应**：前端从真实译文产出反推输出延迟（中位数，`session.ts:432-441`），用 `displayClockMs = playbackMs − 估计延迟` 决定高亮哪一句（`session.ts:463-486`），让"当前句高亮"跟得准。
- **可降级架构**：`MODEL_PROVIDER=mock` 走纯事件流（`ws.py:264`）零配额跑通全链路；报告 LLM 失败时**降级用实时译文拼报告**（`report.py:8`），保证"结束→可下载"永远成立；本地 fixture 演示路径无后端也能合成报告（`session.ts:1794`）。
- **报告四格式**：TXT/SRT/MD/JSON，含中文文件名兼容处理（RFC 5987，`sessions.py:207`）。

**诚实差距 #1（主动讲）**：主 WebSocket 路径目前**无鉴权**——任意 session_id 可连（`ws.py:58`）。**这是"演示→生产"的头号待办**；有意思的是我们的 handoff 路径 token 做得很完整，主路径只是还没补上。

**Q&A 预案**
- *Q：长会议字幕会卡吗？* A：当前展示层做了重挂载/滚动抖动优化；**但配对与时间线是 O(n²) 全量重算、且未虚拟滚动**，几百句以上会劣化——已列入优化项（改进报告 #7）。诚实但有方案。
- *Q：mock 模式是不是"假 demo"？* A：相反，mock 是**工程容错设计**——保证无网络/无配额也能完整演示，真实链路另有 `MODEL_PROVIDER=real`，已用真实 DashScope 在线视频端到端联调过。

## 5. Demo 脚本建议（降低翻车率）

**首选路径：本地测试视频 fixture（`local-test-video-fixture`）**
- 优点：**无需后端/无需配额/不依赖网络**，字幕按播放进度逐句滚出（`session.ts:1444`），13s 处有一个内置纠偏可现场展示高亮，结束自动出报告（`session.ts:1172`）。**最稳，零翻车。**
- 话术："为保证现场稳定我先用内置素材演示完整闭环，真实模型链路我们也已端到端联调过（可放联调录屏/`backend/scripts/e2e_online_url.py` 结果）。"

**进阶（有把握再上）：真实链路**
- `MODEL_PROVIDER=real` + `DASHSCOPE_API_KEY`，用"麦克风/标签页音频"放一段英文演讲。
- **风险**：依赖网络与配额、延迟受网络影响、`#1` 无鉴权（本机演示无碍）。建议**备一段录屏兜底**。

**演示动作清单**：① 选音源 → ② 播放/说话 → ③ 双语字幕逐句滚出（指出"滞后约 1s 贴近真实同传"）→ ④ 出现琥珀高亮纠偏（指出"它在改对前面的句子"）→ ⑤ 结束 → ⑥ 报告区出双语终稿/校正记录/摘要 → ⑦ 下载 SRT/Markdown。

## 6. 面试可能被追问的"硬问题" + 参考回答

| 追问 | 参考回答要点 |
| --- | --- |
| **延迟多少？和讯飞/字节比？** | 不正面比数字——我们是编排型应用，延迟取决于 DashScope LiveTranslate；前端刻意加了 ~1s 展示延迟让节奏**更像真实同传**（`session.ts:86`）。**我们的差异化不在延迟，在"自我纠错"和"产品形态"。** |
| **为什么不做端到端模型？** | 行业 90% 生产部署都用级联（可调试、可热插拔、合规清晰）；端到端是大厂用海量数据自研的重资产路线。**我们用级联 + 在级联之上加一层纠偏**，用更小的代价拿到差异化体验。 |
| **准确率怎么保证？** | 三道防线：引擎内热词/术语 corpus 注入 + 实时跨句纠偏 + 会后全局校正；六大领域差异化 prompt。准确率口径各家不一，我们重点保证"明显错误能被改对、干净句不误纠"。 |
| **成本/计费如何控制？** | 实时纠偏有 6 次/分钟限速；分层模型（flash 便宜跑实时、plus 只在会后跑一次）。**坦白：主 WS 路径暂无鉴权与配额护栏，是生产化第一优先级。** |
| **能扩展到多机/高并发吗？** | 目前会话/事件/handoff 都是单机内存态（适合演示），生产化路线是 Redis/DB 承载 + 断线重连，已规划。 |
| **TTS（语音输出）能用吗？** | **坦白：语音合成接收侧尚未接通，当前是字幕为主**；模型侧已预留 `modalities` 配置，落地接收+播放即可。（**切勿宣称 TTS 已可用**。） |
| **多语种支持到什么程度？** | 实时链路目前**主攻英→中**，UI 暴露的多目标语种部分尚未完全接进后端选型——这是 UI 与能力的一处差距，已知并规划收敛。 |

## 7. 🚩 红线话术（汇报中**不可宣称**的点）

> 这些一旦被现场验证为假，比"没做"更伤分。务必规避或改口为"规划中"。

1. **不要说"TTS/语音播报已经可用"** —— 接收侧未实现（改进报告 #4）。
2. **不要说"客户端时钟双向同步"** —— 实为单向观测（#2）。改口："客户端播放时钟用于同步状态提示。"
3. **不要说"支持上传文件后端 ffmpeg 解码"为现行链路** —— 实际走客户端媒体元素采集，后端那条是死代码（#5）。可正面讲"我们故意让模型输入与画面同源"。
4. **不要承诺"多语种/多模型档位任意切换"** —— 部分是装饰性 UI（#9）。
5. **不要把 mock 演示说成真实模型输出** —— 区分清楚 `mock`（容错演示）与 `real`（真实链路）。

## 8. 一页纸结语（可做最后一张幻灯片）

> **BabelFlux 想清楚了三件事：**
> 1. **做什么**——同传不只是"译得快"，而是"译错了能改对、任何音源都能听、听完能留存"。
> 2. **怎么做**——双层纠偏 + 统一采集管线 + 流对齐与柔和化，站在成熟级联架构上做差异化体验。
> 3. **边界在哪**——鉴权、持久化、真双向同步、TTS 是清晰的"演示→生产"路线图。
>
> **我们既能让它跑起来，也清楚它离生产还差几步——这就是工程成熟度。**
